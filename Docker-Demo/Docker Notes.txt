What is a Virtual Machine :-
A Virtual Machine (VM) is a software-based computer that behaves like a real physical computer. It runs an operating system and applications just like a normal machine, but it exists inside another computer.

A Virtual Machine (VM) is a fully isolated software environment that:
       Behaves like a real physical computer
       Has its own operating system
       Has virtual CPU, RAM, disk, and network
       Runs on top of a hypervisor
Each VM is independent of others.

4. How Docker Provides Isolation:-
In Docker, isolation is the practice of running an application's process in an environment that is separated from the host operating system and other containers. This ensures that each container operates as an independent entity with its own resources, file system, and network. 

How Docker Achieves Isolation:-
      Docker leverages specific features of the Linux kernel to provide this isolation in a lightweight manner, as containers are essentially isolated processes running on a shared host kernel. 	 

The primary mechanisms are:
     Namespaces: These provide an isolated view of system resources. Each container gets its own:
           i.     PID (Process ID) Namespace: Prevents processes in one container from seeing or interfering with processes in another container or on the host. Inside a container, its main process is PID 1.
           ii.    NET (Network) Namespace: Provides a separate network stack, including its own network interfaces, IP addresses, and firewall rules.
           iii.   MNT (Mount) Namespace: Creates an independent filesystem view, so containers cannot access or modify the host's filesystem directly.
           iv.    UTS (UNIX Time-sharing System) Namespace: Allows a container to have its own hostname and domain name.
           v.     IPC (Interprocess Communication) Namespace: Isolates interprocess communication resources.
           vi.    USER Namespace: Allows containers to have a separate mapping of user/group IDs from the host.
           vii.   Control Groups (cgroups): These manage and limit the resources (CPU, memory, disk I/O, etc.) that a container can consume, which prevents a single container from monopolizing all system resources and affecting other operations. 

Key Benefits
     Security: Isolation helps prevent a compromised or malicious container from affecting other containers or the host system.
     Consistency: The self-contained nature ensures applications run consistently across different environments (development, testing, production).
     Conflict Prevention: Applications with conflicting dependencies or port requirements can run simultaneously on the same host without issues.
     Predictable Performance: Resource isolation ensures containers have their allocated resources, leading to more predictable performance.

Difference between virtual machince V/s Docker:-

Docker and Virtual Machines are both technologies used to run applications in isolated environments. However, they differ fundamentally in how they provide isolation, how resources are used, and how applications are deployed.

1. Definition
Virtual Machine (VM):-
A Virtual Machine is a software-based computer that virtualizes hardware. Each VM runs a complete operating system (guest OS) on top of a hypervisor, along with the required applications.

Docker:-
Docker is a containerization platform that virtualizes the operating system. It runs applications in containers that share the host OS kernel, packaging only the application and its dependencies.

2. Level of Virtualization
    Virtual Machine: Hardware-level virtualization
    Docker: Operating system-level virtualization
VMs emulate physical hardware, whereas Docker isolates applications at the OS level.

3. Architecture
Virtual Machine Architecture:-
      Hardware
       └── Host OS
            └── Hypervisor
                 └── Guest OS
                     └── Applications
					 
Docker Architecture:-
    Hardware
     └── Host OS
         └── Docker Engine
             └── Containers
                 └── Applications

4. Operating System and Kernel
Virtual Machine:-
    Each VM has its own OS
    Each OS has a separate kernel
    Can run different operating systems on the same host

Docker:-
    Containers do not have a full OS
    All containers share the host kernel
    OS must be compatible with the host OS

5. Resource Utilization
    VMs allocate fixed resources (CPU, RAM, disk)
    Docker containers share resources dynamically
VMs consume more memory and storage, while Docker containers are lightweight.

6. Performance
    Virtual Machines: Slightly slower due to OS and hypervisor overhead
    Docker: Near-native performance since there is no extra OS layer

7. Startup Time
    Virtual Machine: Takes minutes to boot (OS startup)
    Docker: Starts in seconds (process startup)
	
8. Scalability
    VM scaling: Slow and resource-intensive
    Docker scaling: Fast and efficient
	
11. Use Cases
Virtual Machines:-
    Legacy applications
    Multiple OS requirements
    High-security workloads

Docker:-
    Microservices
    CI/CD pipelines
    Cloud and DevOps environments
	
12. Cost Efficiency
    VMs: Higher infrastructure cost
    Docker: Better resource utilization and lower cost

What is a Virtual Machine (VM)?
 Definition:-  A Virtual Machine (VM) is a software-based computer that behaves like a real physical computer.

Each VM has:
    Virtual CPU
    Virtual RAM
    Virtual Hard Disk
    Virtual Network Card
    Its own Operating System
👉 A VM runs inside another computer, but works like a separate system.

🔹 Example
On a Windows laptop, you can run:
    One VM with Linux
    Another VM with Windows Server
All running at the same time.

3️. Key Components of Virtualization
1️. Host Machine
    The physical machine
    Contains real CPU, RAM, Disk, Network

2️. Host Operating System
    OS installed on physical machine
    (Example: Windows, Linux)

3️. Hypervisor (Very Important)
    Software that creates and manages VMs
    Acts as a bridge between hardware and VMs

4️. Guest Operating System
    OS installed inside the VM
    (Example: Ubuntu, CentOS, Windows Server)
	
4️. What is a Hypervisor?
Definition:-   A Hypervisor is software that allows multiple operating systems to share one physical hardware.

Types of Hypervisors
🅰️ Type-1 Hypervisor (Bare-Metal)
    Installed directly on hardware
    No host OS required
    Used in production & data centers

Examples:
    VMware ESXi
    Microsoft Hyper-V (Server)
    Xen

Advantages:
✔ High performance
✔ High security
✔ Less overhead

🅱️ Type-2 Hypervisor (Hosted)
    Installed on top of an OS
    Used for learning and testing

Examples:
    VirtualBox
    VMware Workstation
    Parallels

Advantages:
✔ Easy to install
✔ Beginner-friendly

Disadvantages:
❌ Slower than Type-1
❌ Depends on host OS

5️. How Virtualization Works (Step-by-Step)
    1️. Physical server has CPU, RAM, Disk
    2️. Hypervisor is installed
    3️. Hypervisor divides resources
    4️. Multiple VMs are created
    5️. Each VM runs its own OS
    6️. Applications run independently in each VM

What is Containerization?
Containerization is a technology that packages:
     Application code
     Libraries
     Dependencies
     Configuration files
into a lightweight unit called a container.

-----  How Containerization Works  -----
Containers run on a Container Engine (example: Docker).
Physical Hardware
│
├── Host Operating System
│
├── Container Engine (Docker)
│    ├── Container 1 (App + Libraries)
│    ├── Container 2 (App + Libraries)
│    └── Container 3 (App + Libraries)

Here On top of the Hardware one  Operating System will run , this is called as Host OS
On top of the Host OS -> Container Engine >> on this Container Engine we can run the containers...(container has complete required things in it like code , software , correct version dependencies so on)

How Containerization Overcomes VM Limitations:- 
1️. No Full OS Required
2. Fast Startup
3. Better Resource Utilization More containers can run on the same hardware ✔ Cost-effective
4. Smaller Size
5. Easy Scalability
       Containers can be created or destroyed quickly , ✔ Perfect for microservices and load balancing

Conclusion:--
Virtual Machines have limitations such as high resource usage, slow startup, and poor scalability.
To overcome these limitations, containerization is used.
Containerization allows applications to run in lightweight containers that share the host OS kernel, resulting in faster startup, better resource utilization, easy scalability, and high portability.

		Creating containers
		Managing images
		Handling networks and volumes
	Listens for Docker Client requests.

Docker Commands:-

	docker --version

	docker ps -a

	docker rm -f webserver

What is a Dockerfile:-
Definition:-  A Dockerfile is a text file that contains a set of instructions used to automatically build a Docker image.

👉 It defines:
	Base operating system
	Application code
	Dependencies
	Configuration
	Startup command

-----  Typical Spring Boot Dockerfile  ----- 
			FROM openjdk:17
			WORKDIR /app
			COPY target/springboot-app.jar app.jar
			EXPOSE 8080
			CMD ["java", "-jar", "app.jar"]

1️. FROM openjdk:17
		Uses OpenJDK 17 as the base image.
		Provides Java Runtime Environment (JRE).
		Spring Boot applications run on this JVM.

2️. WORKDIR /app
		Sets /app as the working directory inside the container.
		All following commands run from this directory.

3. COPY target/springboot-app.jar app.jar
		Copies the built Spring Boot JAR from the host machine into the container.

4️. EXPOSE 8080
		Declares that the Spring Boot application listens on port 8080.
		Common default port for Spring Boot.

5️. CMD ["java", "-jar", "app.jar"]
		Starts the Spring Boot application when the container runs.
		Executes the JAR file using the Java command.

command :-   docker build -t student-app:1.0 .

-t student-app:1.0 → image name & version
.  --> means: “use the current directory as build context”

2. Run Docker Container --> Now run the container:
command:-  docker run -d -p 8080:8080 --name student-container student-app:1.0

Explanation:
-d → detached mode
-p 8080:8080 → hostPort:containerPort
--name → container name

3. Run this command to keep alive the server :-
docker run -d -e SPRING_PROFILES_ACTIVE=dev  -p 8080:8080 student-app:1.0
